# GAPS-2342: poisoned solo-toolchain cache (talos-hq/clud#2342)

Each gap is ticked only when its test in `__tests__/solo-poison-2342.test.ts` is green.

- [x] Save does not check the live toolchain against the key's release; a nightly can be archived under `rustc1.95.0`. Covered by "save refuses a toolchain whose rustc release contradicts the key".
- [x] Save logs both values (expected/observed release and commit hash). Covered by the same test, which asserts `expected=`, `observed=` and `commit=`.
- [x] An unprobeable rustc (non-zero exit) must refuse, not save blind. Covered by "save refuses when rustc cannot be probed".
- [x] A matching toolchain still saves. Covered by "save proceeds when the observed release matches the key".
- [x] Failed repair throws with no fallback. `coldInstallAfterFailedRepair` discards `toolchains/<channel>*` and `update-hashes/<channel>*`, reinstalls and re-verifies, warning once. Covered by "cold-install fallback discards restored toolchain dirs and reinstalls".
- [x] The cold install must fail with a precise message if it is still wrong. Covered by "cold-install fallback fails precisely when the fresh toolchain is still wrong".
- [x] An undeletable poisoned entry produced a warning plus a generic `setup-soldr failed` / "no replacement manifest" failure. Now there is one `core.error` naming `actions: write` and the key, the save is skipped and the job is not failed. Covered by "undeletable poisoned entry gets one diagnostic…" and "deletable poisoned entry is replaced…".
- [x] Parsing of the key's release and of `rustc --version --verbose`. Covered by the two parser tests.
- [ ] NOT TESTED: the `main.ts` / `post.ts` wiring. These are integration seams, so they are exercised only by typecheck and the existing `main.test.ts` / `post.test.ts`. No hosted run has proved them.
- [ ] OPEN: root cause of why `rustup toolchain uninstall && install` still observed 1.98.0-nightly. A poisoned rustup proxy or `settings.toml` override is plausible but has not been proved offline.
- [ ] OPEN: committed `dist/` bundles are not rebuilt. The local `ncc` build is not byte-reproducible: it renumbers modules in `cook/dist`, which this change does not touch.
